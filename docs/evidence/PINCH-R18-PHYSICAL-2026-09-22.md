# Packaged r18 pinch acceptance on the Windows laptop

The [Runtime workflow run 35794436367](https://github.com/omacom/try-omarchy-windows/actions/runs/35794436367) completed its source-locked Windows build, smoke checks, and archive verification. The downloaded portable and source ZIPs passed `SHA256SUMS` and `runtime-build/verify.py` locally. Portable ZIP SHA-256: `a482adf13229bb172fcf7a7ccf1d1684c518742f8c367fca63cde74c117e0198`; source ZIP SHA-256: `45d41e963af6690f25297e24280818885471670f46faba029990a515e0b7fe95`.

The portable ZIP was copied to the physical Windows 11 Business laptop (build 26200, Ryzen 5 5625U, AMD Radeon driver 31.0.21921.1000); its Windows SHA-256 matched. The extracted runtime reported source lock `winq-emu-alpha10-source-r18`, and `qemu-system-x86_64w.exe` SHA-256 `564d900a7839c100c716fd77aa0e40c3a24524eb540ea43347832562a966718c`. The existing test guest booted under that exact executable with WHPX, GPU display, and `virtio-pinch-pci`. Linux reached its desktop.

An interactive Windows scheduled task ran the unchanged engineering launcher with `-experimental-pinch` and the packaged r18 runtime. Synthetic outward and inward two-contact gestures visibly zoomed native Wayland Chromium and returned the test page to its displayed Scale 1.00. The guest remained responsive. With `OMARCHY_PINCH_TRACE=1`, the native bridge recorded recognized contact updates and zero history-query, history-read, or Interaction Context processing failures during the test. The trace was enabled only for this acceptance run.

On the previous r17 build, the user reported that physical pinch worked but was **hard to start**. On r18, the user physically pinched out and back on the same laptop and reported **easier to start**, zoom returning, and normal two-finger scrolling working. A later screenshot still appeared enlarged; it does not independently establish exact final scale, so this record treats return-to-normal as user-reported. The bridge remains opt-in. This test does not establish behavior on other touchpads, Windows 10, Firefox, mixed DPI, or fullscreen.
