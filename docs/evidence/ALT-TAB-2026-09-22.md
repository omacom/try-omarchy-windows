# Focused Alt+Tab acceptance, September 22, 2026

An unsigned Windows amd64 launcher built from the `codex/v1-stable-completion`
worktree passed a focused test on the signed-in AMD Windows 11 laptop. Candidate
SHA-256: `dd483e08f39cff1c6ad027456ab7bd19e1abd75a3e4be3f3a95172aa473aaee8`.
The guest used the published v20 runtime and the retained test installation.

The first candidate forwarded only Tab. The guest received that key, but Alt was
absent and the active guest window did not change. The corrected candidate
forwards both keys as one QMP sequence. With two `foot` windows open, synthetic
Windows Alt+Tab changed the active guest window from address
`0x55d0f6229850` to `0x55d0f62103e0`. Alt+Shift+Tab changed it back.
The launcher log recorded both forwarded keys for each chord.

Synthetic Ctrl+Alt+Tab did not forward either key through the hook and did not
change the active guest window. It remains the keyboard-only host escape; a
plain Ctrl+Alt release would collide with AltGr on international layouts. This
test did not visually certify the host task switcher or test a physical AltGr
keyboard. Those are final-candidate input checks.

The guest powered off cleanly. The prior stable launcher copy was restored with
matching SHA-256, no candidate or QEMU process remained, and the two temporary
interactive scheduled tasks were removed. No guest disk reset or recovery action
was performed.
