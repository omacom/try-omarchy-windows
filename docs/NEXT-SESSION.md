# Try Omarchy Windows continuation — September 23, 2026

The current normal release is [v0.2.0](https://github.com/omacom/try-omarchy-windows/releases/tag/v0.2.0). It contains native Settings from Omarchy, host battery/AC mirroring, r19 live RAM reclamation, approved Windows app launch and revocation, and fullscreen monitor selection. The [signed candidate record](evidence/V020-SIGNED-CANDIDATE-2026-09-23.md) covers the draft manifest, Authenticode signature, physical upgrade, GPU guest, preserved data, app bridge, clean restart and interrupted-update recovery. The user's normal Windows installation was not changed. The Intel/NVIDIA PC remains booted into Omarchy at the owner's request.

Thousands of users and relatively few bug reports are a useful positive signal for the everyday experience. Do not use broad Windows 10 or hardware coverage as an automatic gate for future 0.x releases. Fix reproducible reports as they arrive. Keep the realistic feature gaps active:

- [Windows Hello sudo #165](https://github.com/omacom/try-omarchy-windows/issues/165): opt-in host/PAM request bridge with one-request binding, expiry and password fallback. After the owner set a PIN, the signed-in laptop returned `Available` and an initial approval prompt returned `Verified`. A window-owned key prompt appeared visibly above QEMU, but timed out without approval; `OpenAsync` confirmed no test key was left. The guest sudo bridge and signed challenge still need implementation. Preflight and design notes are on `codex/windows-hello-20260923` without a PR.
- [True LAN bridge #166](https://github.com/omacom/try-omarchy-windows/issues/166): opt-in, reversible signed TAP plus wired-Ethernet path to evaluate. NAT and explicit LAN port forwarding work today. The laptop's only active connection is Wi-Fi, so changing its adapter bindings remotely is unsuitable.
- [Live audio switching #167](https://github.com/omacom/try-omarchy-windows/issues/167): [PR #175](https://github.com/omacom/try-omarchy-windows/pull/175) merged the r20c runtime source and Omarchy PipeWire picker. The [signed pinned candidate](evidence/LIVE-AUDIO-R20-2026-09-23.md) passed on the AMD laptop, including visible GPU desktop, automatic service, saved choices across reboot, active playback/capture, and idle release. Public `v0.2.0` remains on r19; release artifact pinning and suitable-hardware hotplug checks remain.
- [Embedded Windows app windows #160](https://github.com/omacom/try-omarchy-windows/issues/160): phase 1 launch-and-return ships in v0.2.0. Window capture, input, focus, scaling and lifecycle are a separate milestone.
- [Direct application drops #174](https://github.com/omacom/try-omarchy-windows/issues/174) tracks delivery of a Windows file drop to a Wayland app rather than the current Downloads fallback. [Intel/NVIDIA Venus #173](https://github.com/omacom/try-omarchy-windows/issues/173) tracks a concrete older-runtime Vulkan/Godot failure without switching the owner's PC away from Omarchy. [ARM64 #131](https://github.com/omacom/try-omarchy-windows/issues/131), [interface translation #127](https://github.com/omacom/try-omarchy-windows/issues/127), and USB device reports remain open or documented. Pinch stays opt-in while real device reports guide defaults.
